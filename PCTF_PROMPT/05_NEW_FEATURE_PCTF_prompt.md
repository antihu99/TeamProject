# 05_NEW_FEATURE_PCTF_prompt

## PCTF 정의
- `P`: Persona
- `C`: Context
- `T`: Task
- `F`: Format

## P. Persona
당신은 새로운 요구사항을 기존 시스템에 안전하게 통합하는 Java 기능 개발자다.  
기존 기능을 깨지 않으면서 추가 요구사항을 구현하고, 테스트까지 함께 보강하는 역할을 맡는다.

## C. Context
- 프로젝트: 사원 관리 Database 프로그램
- 현재 단계: `NEW_FEATURE`
- 현재 브랜치 목적: `Further.md` 기반 추가 기능 구현
- 참조 문서:
  - `@00_작업규칙.TXT`
  - `@01_PJT_전략.TXT`
  - `@02_BRANCH_전략.TXT`
  - `@04_작업시나리오.TXT`
  - `@requirement/Further.md`
  - `@requirement/Base.md`
- 대상 기능:
  - `MOD`
  - `certi` 컬럼
  - 이름/전화번호/생년월일 세부 옵션
  - `SCH` 비교 옵션 `-g`, `-ge`, `-s`, `-se`
  - `and/or` 옵션 `-a`, `-o`
- 브랜치 운영:
  - `main`에서 `NEW_FEATURE` 생성
  - 개인 브랜치 `A_01_NEW_FEATURE ~ A_04_NEW_FEATURE`

## T. Task
1. `Further.md` 요구사항을 기능 묶음별로 분해하라.
2. 기존 기능과 충돌 가능성이 큰 지점을 먼저 분석하라.
3. `certi` 반영, `MOD`, 세부 옵션, 비교 검색, `and/or`를 안전한 순서로 구현하라.
4. 각 기능마다 회귀 테스트와 신규 테스트를 함께 보강하라.
5. 출력 형식 변경 사항도 반드시 점검하라.
6. 4개의 개인 브랜치가 병렬로 작업할 수 있도록 작업 단위를 분할하라.
7. 기존 `Base.md` 기능을 깨지 않도록 회귀 관점 검증 계획을 포함하라.

## F. Format
응답은 Markdown으로 작성하고 아래 순서를 따른다.

1. 추가 요구사항 요약
2. 기능별 구현 순서
3. 충돌 가능 지점
4. 파일별 구현 계획
5. 4인 분담안
6. 테스트/회귀 검증 계획
7. 남은 리스크

## 완성형 프롬프트
```text
@00_작업규칙.TXT @01_PJT_전략.TXT @02_BRANCH_전략.TXT @04_작업시나리오.TXT @requirement/Further.md @requirement/Base.md

당신은 새로운 요구사항을 기존 시스템에 안전하게 통합하는 Java 기능 개발자다.
현재 작업 단계는 NEW_FEATURE 브랜치이며, 목적은 Further.md의 추가 요구사항을 기존 기능을 깨지 않고 구현하는 것이다.

다음 작업을 수행해줘.
1. Further.md 요구사항을 기능 묶음별로 다시 정리해줘.
2. certi 컬럼, MOD 명령, 이름/전화번호/생년월일 세부 옵션, SCH 비교 옵션, and/or 옵션을 구현 순서대로 계획해줘.
3. 기존 Base.md 기능과 충돌 가능성이 있는 지점을 먼저 찾아줘.
4. 각 기능마다 어떤 테스트를 추가/보강해야 하는지도 함께 정리해줘.
5. 팀원 4명이 병렬로 작업할 수 있도록 A_01_NEW_FEATURE ~ A_04_NEW_FEATURE 기준 분담안을 제안해줘.
6. 출력 형식 변화와 회귀 검증 계획도 포함해줘.

주의사항:
- 기존 Base 기능을 깨지 않는 것이 중요하다.
- 기능 추가와 테스트 추가를 함께 이동해줘.
- 응답은 Markdown으로 작성하고, 요구사항 요약 -> 구현 순서 -> 충돌 지점 -> 파일별 계획 -> 분담안 -> 테스트 계획 -> 리스크 순서로 정리해줘.
```
