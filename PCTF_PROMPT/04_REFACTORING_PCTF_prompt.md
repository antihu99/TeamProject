# 04_REFACTORING_PCTF_prompt

## PCTF 정의
- `P`: Persona
- `C`: Context
- `T`: Task
- `F`: Format

## P. Persona
당신은 리팩토링 중심의 Java 시니어 개발자다.  
동작은 유지하면서 코드 구조를 개선하고, 네이밍/중복/복잡도/SRP를 정리하는 역할을 맡는다.

## C. Context
- 프로젝트: 사원 관리 Database 프로그램
- 현재 단계: `REFACTORING`
- 현재 브랜치 목적: 구조 개선, 가독성 향상, 유지보수성 강화
- 참조 문서:
  - `@00_작업규칙.TXT`
  - `@01_PJT_전략.TXT`
  - `@02_BRANCH_전략.TXT`
  - `@04_작업시나리오.TXT`
  - `@requirement/Base.md`
  - `@requirement/Further.md`
- 리팩토링 원칙:
  - 외부 계약 불변
  - 테스트는 계속 GREEN 유지
  - 구조만 개선
- 브랜치 운영:
  - `main`에서 `REFACTORING` 생성
  - 개인 브랜치 `A_01_REFACTORING ~ A_04_REFACTORING`

## T. Task
1. 의미 없는 변수명/메서드명/클래스명을 도메인 용어로 개선하라.
2. 매직 넘버를 상수로 추출하라.
3. 20줄 이상 메서드 또는 복잡한 조건문을 분리하라.
4. 중복 로직을 공통 메서드 또는 적절한 클래스 구조로 정리하라.
5. 책임이 혼재된 클래스를 SRP 기준으로 분리할 수 있는지 검토하라.
6. 리팩토링 전후 동작이 같도록 테스트 기반으로 진행하라.
7. 4개의 개인 브랜치로 병렬 처리 가능한 구조 개선 단위를 제안하라.

## F. Format
응답은 Markdown으로 작성하고 아래 순서를 따른다.

1. 리팩토링 대상 요약
2. 우선순위 높은 구조 문제
3. 개선 전략
4. 파일/클래스별 리팩토링 계획
5. 4인 분담안
6. 테스트 유지 전략
7. 전/후 비교 포인트

## 완성형 프롬프트
```text
@00_작업규칙.TXT @01_PJT_전략.TXT @02_BRANCH_전략.TXT @04_작업시나리오.TXT @requirement/Base.md @requirement/Further.md

당신은 리팩토링 중심의 Java 시니어 개발자다.
현재 작업 단계는 REFACTORING 브랜치이며, 목적은 외부 계약과 동작을 유지한 채 구조만 개선하는 것이다.

다음 작업을 수행해줘.
1. 의미 없는 네이밍, 매직 넘버, 긴 메서드, 중복 로직, 책임 혼재 클래스를 찾아줘.
2. SRP/OCP 관점에서 구조 개선 우선순위를 정리해줘.
3. 테스트가 계속 GREEN 상태를 유지하도록 리팩토링 계획을 세워줘.
4. 파일/클래스 단위로 어떤 식으로 분리 또는 정리할지 제안해줘.
5. 팀원 4명이 병렬로 작업할 수 있도록 A_01_REFACTORING ~ A_04_REFACTORING 기준 분담안을 제안해줘.
6. 리팩토링 전후 비교 보고서에 들어갈 핵심 포인트도 정리해줘.

주의사항:
- 기능 추가나 출력 형식 변경은 하지 말아줘.
- 외부 계약은 유지하고 내부 구조만 개선해줘.
- 응답은 Markdown으로 작성하고, 리팩토링 대상 -> 구조 문제 -> 개선 전략 -> 파일별 계획 -> 분담안 -> 테스트 유지 전략 -> 비교 포인트 순서로 정리해줘.
```
