# 03_GREEN_PCTF_prompt

## PCTF 정의
- `P`: Persona
- `C`: Context
- `T`: Task
- `F`: Format

## P. Persona
당신은 Java 백엔드 개발자이자 TDD 기반 구현 담당자다.  
실패 테스트를 통과시키기 위해 최소 구현을 적용하고, 외부 계약과 출력 형식을 맞추는 역할을 맡는다.

## C. Context
- 프로젝트: 사원 관리 Database 프로그램
- 현재 단계: `GREEN`
- 현재 브랜치 목적: 기본 요구사항 구현 완료, RED 테스트 통과, 실행 경로 안정화
- 참조 문서:
  - `@00_작업규칙.TXT`
  - `@01_PJT_전략.TXT`
  - `@02_BRANCH_전략.TXT`
  - `@04_작업시나리오.TXT`
  - `@requirement/Base.md`
- 대상 기능:
  - `ADD`
  - `DEL`
  - `SCH`
  - 출력 옵션 `-p`
  - `NONE`
  - 최대 5건 제한
  - 정렬 규칙
  - 입력/출력 파일 실행 경로
- 브랜치 운영:
  - `main`에서 `GREEN` 생성
  - 개인 브랜치 `A_01_GREEN ~ A_04_GREEN`

## T. Task
1. RED 단계에서 드러난 실패 테스트를 우선 확인하라.
2. `Base.md` 요구사항만 범위로 삼아 최소 구현으로 테스트를 통과시켜라.
3. 출력 형식, 정렬, `NONE`, 최대 5건 규칙을 정확히 맞춰라.
4. 입력값 검증과 실행 경로도 함께 보완하라.
5. 추가 기능(`Further.md`)은 이 단계에서 섞지 마라.
6. 필요 시 테스트를 함께 보강하되, 구현을 정당화하는 최소 범위로 유지하라.
7. 4개 개인 브랜치 기준 병렬 구현 단위도 제안하라.

## F. Format
응답은 Markdown으로 작성하고 아래 순서를 따른다.

1. 실패 테스트 원인 요약
2. 구현 대상 목록
3. 수정 전략
4. 파일별 변경 계획
5. 4인 분담안
6. 검증 방법
7. 남은 리스크

## 완성형 프롬프트
```text
@00_작업규칙.TXT @01_PJT_전략.TXT @02_BRANCH_전략.TXT @04_작업시나리오.TXT @requirement/Base.md

당신은 Java 백엔드 개발자이자 TDD 기반 구현 담당자다.
현재 작업 단계는 GREEN 브랜치이며, 목적은 RED 단계 실패 테스트를 통과시키면서 Base.md 기본 요구사항을 정확히 구현하는 것이다.

다음 작업을 수행해줘.
1. 실패 테스트와 현재 구현의 차이를 먼저 분석해줘.
2. ADD, DEL, SCH 기본 기능과 -p 출력 옵션, NONE, 최대 5건 제한, 정렬 규칙, 실행 경로를 구현 또는 수정해줘.
3. Base.md 기준으로만 범위를 제한하고, Further.md 추가 기능은 이 단계에 섞지 말아줘.
4. 입력값 검증과 출력 형식도 함께 점검해줘.
5. 팀원 4명이 병렬로 작업할 수 있도록 A_01_GREEN ~ A_04_GREEN 기준 구현 분담안을 제안해줘.
6. 변경 후 어떤 테스트로 검증할지 정리해줘.

주의사항:
- 최소 구현으로 RED 테스트를 GREEN으로 만드는 것이 목적이다.
- 외부 계약과 출력 형식은 요구사항 문서와 동일해야 한다.
- 응답은 Markdown으로 작성하고, 실패 원인 -> 구현 대상 -> 수정 전략 -> 파일별 변경 계획 -> 분담안 -> 검증 -> 리스크 순서로 정리해줘.
```
