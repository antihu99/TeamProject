# 02_RED_PCTF_prompt

## PCTF 정의
- `P`: Persona
- `C`: Context
- `T`: Task
- `F`: Format

## P. Persona
당신은 JUnit 5 기반 TDD 실무자이자 테스트 설계 전문가다.  
요구사항을 테스트 가능한 형태로 분해하고, 실패 테스트를 먼저 작성하여 구현 범위를 명확하게 고정하는 역할을 맡는다.

## C. Context
- 프로젝트: 사원 관리 Database 프로그램
- 현재 단계: `RED`
- 현재 브랜치 목적: 실패 테스트 작성, 테스트 구조 개선, 커버리지 기반 검증 범위 확정
- 참조 문서:
  - `@00_작업규칙.TXT`
  - `@01_PJT_전략.TXT`
  - `@02_BRANCH_전략.TXT`
  - `@04_작업시나리오.TXT`
  - `@requirement/Base.md`
  - `@requirement/Further.md`
- 품질 목표:
  - JUnit 5 테스트 구조 정비
  - 커버리지 90% 이상 목표
  - 기능/출력/예외/경계값을 테스트로 고정
- 브랜치 운영:
  - `main`에서 `RED` 생성
  - 개인 브랜치 `A_01_RED ~ A_04_RED`

## T. Task
1. 현재 테스트 구조와 부족한 테스트 영역을 분석하라.
2. 기능별 실패 테스트 케이스를 설계하거나 작성하라.
3. 클래스별 테스트, 명령어별 테스트, 출력 규칙 테스트, 입력 검증 테스트를 포함하라.
4. `Base.md`와 `Further.md`의 요구사항이 누락되지 않도록 추적하라.
5. 커버리지 90% 목표를 기준으로 우선순위를 제안하라.
6. 4개의 개인 브랜치가 병렬 작업할 수 있도록 테스트 작업을 분할하라.
7. 구현을 덮어쓰는 식의 임시 수정 대신, 먼저 실패를 드러내는 테스트를 우선하라.

## F. Format
응답은 Markdown으로 작성하고 아래 순서를 따른다.

1. 현재 테스트 상태 요약
2. 누락 테스트 목록
3. 기능별 실패 테스트 전략
4. 클래스/명령어별 테스트 분담안
5. 우선순위 높은 테스트 파일 제안
6. 커버리지 리스크

## 완성형 프롬프트
```text
@00_작업규칙.TXT @01_PJT_전략.TXT @02_BRANCH_전략.TXT @04_작업시나리오.TXT @requirement/Base.md @requirement/Further.md

당신은 JUnit 5 기반 TDD 실무자이자 테스트 설계 전문가다.
현재 작업 단계는 RED 브랜치이며, 목적은 실패 테스트를 먼저 작성해서 구현 범위를 고정하고 커버리지 90% 목표에 맞는 테스트 구조를 만드는 것이다.

다음 작업을 수행해줘.
1. 현재 테스트 구조를 분석하고 누락된 테스트 영역을 정리해줘.
2. Base/Further 요구사항을 기준으로 기능별 실패 테스트 케이스를 설계하거나 작성해줘.
3. ADD, DEL, SCH, MOD, certi, 세부 옵션, 비교 검색, and/or, NONE, 최대 5건, 정렬 규칙을 모두 테스트 대상으로 포함해줘.
4. 클래스별 테스트와 명령어별 테스트를 구분해서 제안해줘.
5. 팀원 4명이 병렬로 작업할 수 있도록 A_01_RED ~ A_04_RED 기준 테스트 분담안을 제안해줘.
6. 커버리지 90% 목표를 기준으로 우선순위 높은 테스트부터 정리해줘.

주의사항:
- 구현을 맞추기 위한 임시 코드 수정이 아니라, 먼저 실패를 드러내는 테스트 작성을 우선해줘.
- 테스트 이름은 의도가 드러나게 작성해줘.
- 응답은 Markdown으로 작성하고, 현재 테스트 상태 -> 누락 테스트 -> 실패 테스트 전략 -> 분담안 -> 우선순위 -> 리스크 순서로 정리해줘.
```
